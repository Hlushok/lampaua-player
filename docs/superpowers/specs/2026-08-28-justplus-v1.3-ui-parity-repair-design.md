# UA Player Just+ v1.3 UI and Subtitle Parity Repair

## Goal

Replace UA Player's partially reimplemented Just+ interface with the actual responsive
behavior of Just+ Player `v1.3.0` at commit
`21e1c334bc04b67afb4515b0e7d8dae50c962949`, while preserving UA Player's identity,
LampaUA/LAMPA contracts, playback recovery, update source, signing identity, and private
`2.0.0 (20)` delivery boundary.

This design supersedes the compact-control, custom `More` grouping, and selectable
translation-target decisions in
`docs/superpowers/specs/2026-08-28-justplus-v1.3-parity-design.md`. The earlier document
remains authoritative for playback, playlist, skip-source, privacy, and UA compatibility
requirements where this repair does not explicitly replace them.

## Confirmed Root Causes

The reported behavior is not one isolated color or orientation bug. The port retained the
features but replaced several adaptive Just+ UI mechanisms with fixed UA-specific layouts.

- The current quality row reserves `112dp` for the badge, `128dp` for bitrate, `42dp` for
  the check mark, plus margins and padding. Inside the portrait panel this leaves almost no
  width for its weighted title block, matching the supplied screenshot where only fragments
  of the labels remain visible.
- The current LAMPA header uses a fixed `136dp × 76dp` poster, fixed accent gaps, a fixed
  clock block, a `94dp` card height, and an `8dp` top margin. On a narrow portrait window the
  title column collapses; the card also does not reserve the stable status-bar/cutout inset.
- The current settings XML flattened Just+'s secondary-subtitle and online-search screens,
  removed their parent summaries and dependent-row enablement, and placed related controls
  in different locations. This makes auto-translation difficult to discover and makes
  inactive rows look active.
- `PlayerButtonPlacement` and the UA `More` menu use user pinning and custom defaults to
  relocate actions. Just+ instead places controls by semantic cluster, device class, and
  real-time availability. The custom layer is why too many actions appear hidden or in
  unexpected groups.

## Product Decisions

- Just+ `v1.3.0` is authoritative for user-facing layout, control placement, grouping,
  visibility, focus, and preference hierarchy.
- UA Player remains authoritative for colors, logo, strings, package name, updater,
  LampaUA/LAMPA parsing and results, Watch Together identity, recovery policies, server
  skips, and signing.
- Translation may consume any source language supported by the Just+ pipeline, but every
  machine-translated result targets Ukrainian (`ukr`). There is no target-language picker
  or persisted target selection.
- Provider and translation-endpoint switches follow Just+: they remain available for
  diagnostics in debug builds and hidden in release builds. Hiding those diagnostic rows
  must not hide the online-search or Ukrainian auto-translation behavior itself.
- Version remains `2.0.0`, version code `20`, application id remains
  `com.lampaua.player`, and no tag, release, public APK, push, or pull request is created
  without a separate direct request.

## Adaptive UI Foundation

Adapt Just+'s `UiMetrics` sizing model and related long-text fitting rather than adding
orientation-specific constants to each dialog. The model derives dimensions from
`Configuration.screenWidthDp`, `screenHeightDp`, font scale, and TV classification.

The same metrics instance drives:

- phone portrait, phone landscape, tablet, and TV text sizes;
- side-panel width, row minimum height, padding, and focus geometry;
- header poster and clock sizing;
- safe horizontal content grids and TV overscan;
- compacting or wrapping optional row metadata without shrinking the primary label to zero.

Configuration changes rebuild or reapply these metrics without restarting playback.
Interactive rows keep a minimum usable title width at every supported phone width. Optional
bitrate/detail text wraps, moves below the title, or disappears before the action label is
allowed to collapse.

## Player Header and System Insets

The current LAMPA metadata remains the data source for poster, title, episode, media details,
clock, and finish time. Their layout follows the donor's responsive header rules.

- Use the status-bar/cutout inset that ignores transient visibility on Android 30 and newer,
  so the header does not jump when immersive bars hide or reappear.
- Apply safe left/right insets symmetrically and retain TV overscan behavior.
- On narrow portrait screens, scale the poster and clock through `UiMetrics`; the title and
  media summary retain useful width and ellipsize only after the adaptive reductions.
- Preserve UA navy/gold card styling, but do not use a fixed height that clips larger fonts.
- The visible card, focus state, and controller visibility remain synchronized. No status
  bar, display cutout, poster, or clock may cover the title/details column.

## Picker and Dialog Behavior

Quality, audio, subtitle, playlist, speed, offset, and settings pickers use the Just+ side
panel and row behavior, restyled with UA colors. They no longer each invent a centered
fixed-width layout.

- Panel width comes from the shared metrics and respects system/cutout insets.
- The primary row label is weighted and always receives usable width.
- Secondary metadata and bitrate are `wrap_content` and bounded; they yield to the primary
  label on narrow screens.
- The selected item, D-pad focus owner, touch target, and check mark remain distinct and
  visible in both orientations.
- Rows use donor long-text fitting and may wrap to a second line at larger font scales.
- Back closes one picker level and returns focus to the originating player control.
- UA navy/blue/gold drawables remain presentation only; text visibility must not depend on
  a one-time traversal of currently inflated list children.

## Player Controls and Availability

Remove the custom pin/unpin-to-`More` policy as the source of control placement. Use the
Just+ `v1.3.0` assembly rules as the behavioral reference:

- controls are arranged in the donor's semantic clusters;
- phone display controls use the donor's header/bottom placement;
- TV controls use the donor's bottom clusters and focus order;
- playlist, quality, subtitle, PiP, rotation, lock, skip, and room actions appear only when
  their donor availability condition is true;
- unavailable actions appear nowhere, while available user actions always have one normal
  route and are never reachable only through a hidden fallback menu;
- UA-only actions are inserted into the matching donor surface: Watch Together with room
  controls, update with application status, and UA settings through the normal settings
  route and launcher state.

The visible `playerButtons` pinning screen and `PlayerButtonPlacement` behavior are retired.
Existing `showButton*` values may remain unread legacy keys, but they no longer override
donor availability. No migration deletes unrelated preferences.

## Subtitle Settings Hierarchy

Restore the donor's four-row subtitle category:

1. Primary subtitle language priority.
2. A secondary-subtitle screen containing mode, secondary language priority, size, text
   color, and background.
3. An online-subtitle screen whose parent summary shows the current search mode.
4. An appearance screen containing embedded-style policy, scale, text color, background,
   edge, bold behavior, and the UA live preview.

The online-subtitle screen contains:

- the donor search-mode list;
- a visible switch titled and summarized as Ukrainian auto-translation;
- the donor manual-language prompt when applicable;
- debug-only source and translation-backend diagnostics.

When search mode is off, its dependent rows remain visible but disabled. When translation is
off, only translation-specific diagnostics are disabled. Parent rows always expose their
current mode in the summary so the features are discoverable without opening every screen.

## Ukrainian Auto-Translation Contract

`subtitleTranslateOn` is the user-visible opt-in. When online search is active and an
original Ukrainian subtitle is unavailable, the player searches the donor-supported source
languages and translates the best valid candidate to `ukr` using the complete Just+ backend
fallback, batching, validation, and atomic cache workflow.

- The translation target is a constant, not a preference.
- Loading preferences removes the legacy `languageSubtitleTranslate` key.
- Changing search or translation behavior clears only affected translated cache entries.
- A translated result attaches as the primary Ukrainian subtitle. Secondary-subtitle
  language choices continue to search original tracks and never silently change the
  translation target.
- Translation does not require Ukrainian to be manually added to the primary language list;
  enabling Ukrainian auto-translation is itself an explicit request for that fallback.
- Search tries a valid original Ukrainian result before translating.
- Success, progress, and failure messages explicitly say Ukrainian translation and never
  expose provider names, subtitle text, media URLs, headers, credentials, or room state.
- Failed, partial, stale-generation, wrong-item, or structurally invalid translations are
  never attached or cached as successful results.

## State, Error Handling, and Compatibility

- Player/session identity checks continue to guard every asynchronous subtitle result.
- A configuration change cannot restart a search, duplicate an attachment, spend playback
  recovery attempts, or lose primary/secondary offsets.
- Empty-state, external `ACTION_VIEW`/`SEND`, LAMPA playlist, IPTV, Watch Together, skip,
  result, and recovery contracts remain unchanged.
- Settings and legacy preference migration are fail-safe: malformed values use existing
  defaults, and obsolete target/button keys cannot crash startup.
- The signing certificate must remain SHA-256
  `749d118bc8a16a7c0464b8dd0498c53da8a86a668d8f09f551e60cf7d88ee15e`.

## Verification Design

Implementation begins with failing tests that reproduce the confirmed regressions.

### Pure/JVM coverage

- shared metrics and row-allocation policies at `320dp`, `360dp`, `411dp`, `600dp`, and TV
  widths in portrait and landscape;
- font scales `1.0`, `1.3`, and `1.5`, proving primary labels retain positive usable width;
- stable top inset selection with visible and hidden status bars;
- donor control placement and runtime availability for phone and TV;
- settings hierarchy, parent summaries, dependent-row enablement, and removal of the
  visible player-button pinning screen;
- fixed Ukrainian target migration and absence of a target picker;
- translation from multiple source languages to `ukr`, original-Ukrainian precedence,
  disabled-search behavior, cache invalidation, and stale-item rejection;
- existing LAMPA, playlist, secondary subtitle, offset, Watch Together, skip, recovery,
  privacy, updater, and package contracts.

### Android verification

- full unit suite;
- release lint with zero errors/fatals;
- debug and release builds;
- resource compilation and `git diff --check`;
- package/version/ABI inspection, `zipalign`, v1/v2/v3 signature verification, certificate
  digest, and final APK SHA-256.

### Device verification

The local APK is checked on a real phone in portrait and landscape for every player picker,
the top poster/title/clock block, status-bar transitions, font scaling, subtitle settings,
original Ukrainian search, Ukrainian auto-translation from a foreign source, secondary
subtitles, and offsets. Android TV verification covers D-pad focus, control placement,
Back, lock, pause, dimming, and grouped settings behavior. Any unavailable hardware or
third-party subtitle result is reported as unverified rather than inferred from compilation.

## Delivery Boundary

The deliverable is source changes and a freshly built, locally signed private APK. No
repository push, branch publication, pull request, tag movement, GitHub Release change, or
public artifact upload is part of this work without a separate direct command.
