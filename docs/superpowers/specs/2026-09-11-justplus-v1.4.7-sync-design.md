# UA Player sync with Just+ v1.4.7

## Goal

Bring UA Player's Android player core and user experience from the previously
integrated Just+ v1.4.2 baseline to the complete stable Just+ v1.4.7 state,
including fixes that already exist upstream, while retaining only the defined
UA Player product and integration layer.

## Verified source and target

- Donor repository: `https://github.com/just-plus-player/just-plus-player`.
- The donor's primary branch is named `master`; it has no `main` branch.
- Stable donor target: tag `v1.4.7`, commit
  `f26a71e8e931ed1859a162bd3829d66419aba2b9`, dated 2026-09-10.
- Previously integrated donor baseline: commit
  `9b2479e0c6ed83b468b1427207f0f4fe15ec64b8` from the v1.4.2 release line.
- The verified donor range contains 35 commits and changes 21 paths.
- UA Player target branch: only local `main`, fast-forwarded to
  `origin/main` commit `f600d9e86e55b22d546447078fb62500e3bff7cb`
  before this work starts.

## Source-of-truth rule

For every path changed by the donor range, the v1.4.7 implementation is the
source of truth for player-core behavior. The update must not select only the
visually obvious fixes. Each donor change is classified as one of:

1. imported as-is because it is pure player core or a bundled runtime library;
2. merged semantically because the same file contains an approved UA hook;
3. excluded with a written reason because it changes donor branding,
   publication, signing, package identity, or versioning rather than runtime
   behavior.

No old UA implementation of a core behavior is retained merely because it
already exists. When donor v1.4.7 and UA Player implement the same behavior,
the donor behavior wins.

## Donor behavior covered by the update

The complete range includes, at minimum:

- held TV seek pacing, stride selection, progress feedback, and media-duration
  bounds;
- handling of the TV remote `EXIT` key;
- decoded surround as the default plus an explicit bitstream/passthrough
  preference;
- decoder recreation fallback that keeps playback alive on affected TV boxes;
- richer diagnostic history around failures;
- preservation of the active audio route without stopping playback;
- transfer statistics on their own line above the seek bar;
- bottom-control positioning based on measured height and full-height control
  scrims;
- the donor settings, strings, layout, build-tool, Media3 library, and bundled
  decoder-library changes required by those behaviors.

This list is explanatory, not an allowlist: all 35 commits remain in scope.

## UA layer that must remain

The sync preserves these product-owned behaviors:

- package `com.lampaua.player`, UA Player name, icon, blue-and-gold theme, and
  `Powered by KinoHub` presentation;
- LAMPA/LampaUA launch and result contracts, headers, title/poster metadata,
  quality variants, external subtitles, playlist/session state, and resume
  position;
- launcher actions, IPTV, and LAMPA playlists, without maintaining a separate
  core panel geometry;
- Watch Together and its LAMPA-compatible room protocol;
- server skip sources, session segment offsets, skip undo, and restored
  per-episode skip state;
- subtitle search, secondary subtitles, timing/style controls, and automatic
  translation from any supported source language with Ukrainian as the only
  target;
- compatible signing identity and user-controlled UA Player versioning.
- the existing no-telemetry privacy boundary: diagnostic data stays local
  unless the user explicitly shares/uploads a report; the donor Sentry client
  and repository-specific telemetry bootstrap are not introduced.

UA-specific code may adapt to a changed donor interface, but must not override
the donor's layout, visibility, focus, Back, orientation, decoder, seek, audio,
or recovery policy.

## Merge architecture

### 1. Build and bundled libraries

Synchronize the donor Gradle/plugin/wrapper and `app/libs` changes as a single
coherent Media3 runtime set. Preserve UA Player's application ID, namespace
compatibility, flavor/version rules, release signing inputs, archive naming,
and ABI policy. The AAR files must not be mixed across donor versions.

### 2. Player core

Use v1.4.7 as the reference for `App`, `PlayerActivity`, `Prefs`, `Utils`,
`CustomPlayerView`, the new bottom-bar layout helper, and player control
resources. Reapply UA behavior through the narrowest existing integration
points. Large UA blocks in `PlayerActivity` are retained only when they serve
one of the approved UA contracts above.

### 3. Settings and resources

Adopt the donor's preference hierarchy, defaults, labels, conditional
visibility, phone/TV behavior, focus navigation, and responsive geometry.
Ukrainian strings and UA colors are layered over that structure. A setting
must not be hidden or regrouped unless v1.4.7 does so, except that the subtitle
translation target picker remains absent because the target is always
Ukrainian.

### 4. Integration reconciliation

After the donor core is in place, reconcile LAMPA intents, playlists, Watch
Together, skip services, subtitle translation, and launcher UI against the new
core lifecycle. Incoming session data remains owned by LAMPA/LampaUA and must
not leak into the player's persistent standalone resume state.

### 5. Regression protection

For each upstream behavior that does not already have equivalent coverage,
add a focused test before or together with its integration. Preserve and run
the existing UA contract, subtitle, playlist, skip, orientation, focus,
recovery, and resource-contract tests. Tests must check behavior, not exact
private method layout.

## Data flow and lifecycle expectations

1. Android or LAMPA launches UA Player with a media URI and optional session
   extras.
2. The UA contract parser validates and normalizes product-specific extras.
3. The v1.4.7 player core owns renderer creation, audio mode, seeking,
   controls, buffering, recovery, orientation, and teardown.
4. Optional UA services add subtitles, playlists, rooms, and skip segments
   through their existing bounded interfaces.
5. Session state and the result intent are returned to the launcher without
   corrupting standalone player preferences.

Any new donor preference receives the donor default on existing and fresh
installs unless a UA product constraint above explicitly overrides it.

## Error handling

- Decoder recreation and audio-route failures follow the donor's v1.4.7
  recovery path before UA Player exposes a terminal error.
- Diagnostic reporting includes the donor's new action history inside the
  existing UA local report while retaining UA-safe redaction and explicit
  user-initiated upload behavior.
- Invalid LAMPA extras, playlist entries, subtitle data, or skip payloads fail
  closed for that optional feature and must not stop otherwise valid playback.
- No fallback may silently switch package identity, translation target, signing
  identity, or persistent-session ownership.

## Verification and acceptance

The update is acceptable only when all of the following are fresh and pass:

1. A path-by-path donor audit accounts for all 21 changed paths and all 35
   commits, including an explicit reason for every intentional exclusion.
2. Focused regression tests cover the newly integrated donor behaviors and all
   touched UA contracts.
3. The complete unit-test suite reports zero failures and errors.
4. `lintLatestUniversalRelease` reports zero fatal issues and zero errors;
   non-blocking warnings are counted.
5. `assembleLatestUniversalDebug` and `assembleLatestUniversalRelease`
   complete successfully with a coherent bundled-library set.
6. The final installable local APK is checked with the project verifier plus
   `zipalign`, `apksigner`, `aapt2`, and `apkanalyzer` for package, version,
   debuggable state, ABI set, v1/v2/v3 signatures, and the compatible signing
   certificate.
7. If an ADB device is available, smoke-test launch, playback, orientation,
   subtitles, TV navigation, seeking, audio mode, playlist, and Back/EXIT. If
   none is available, report runtime QA as still pending rather than inferring
   it from builds.

## Version, delivery, and publication boundary

- Keep `versionName 2.0.0` and `versionCode 20` during this local update unless
  the user separately chooses a new version.
- Produce a clearly named local test APK after verification.
- Do not create or move a tag, push to GitHub, replace the public v2.0.0 asset,
  or publish another release without a separate direct command.

## Out of scope

- Windows UA Player and LampaUa Desktop.
- Lampac server/module development.
- Unrelated refactoring outside the donor range or the required UA integration
  reconciliation.
