# UA Player Just+ v1.3 Functional Parity Design

## Goal

Bring every technically applicable user-facing feature and playback fix from Just+ Player
`v1.3.0` into UA Player while keeping UA Player's design, Android package, signing identity,
LampaUA/LAMPA contracts, updater, and existing recovery behavior.

The reviewed source snapshots are:

- UA Player working branch: `codex/fix-2.0.0-feedback` at `9a6f4eb`, including the current
  uncommitted empty-state and compact-control work.
- Just+ Player release: `v1.3.0`, commit
  `21e1c334bc04b67afb4515b0e7d8dae50c962949`.
- Just+ comparison base: `v1.2.0`, commit
  `611e737e43fe72925cbea5233327f2d5af4ac2d2`.

The Just+ `v1.2.0...v1.3.0` range changes 30 production files and adds roughly 9,780
lines. UA Player is already substantially divergent, so parity means porting behavior into
UA boundaries, not replacing whole files.

## Approved Product Decisions

- Match the Just+ `v1.3.0` feature set, not its branding.
- Keep UA Player's navy, blue, and gold visual language, icons, TV banner, Ukrainian-first
  copy, launcher empty state, and compact control bar.
- Machine translation targets the language selected by the user, as in Just+ `v1.3.0`.
  Ukrainian remains the default target for UA Player.
- Subtitle source and translation endpoint switches remain internal in normal builds. Users
  configure behavior, languages, and appearance, not a list of unofficial providers.
- Include the upstream multi-source skip finder and session skip offset, but keep launcher
  segments and the UA Lampac skip service at higher priority.
- Do not add automatic telemetry. Diagnostic sharing or upload is always explicit.
- Keep version `2.0.0`, version code `20`, and package `com.lampaua.player` during this local
  validation cycle.
- Source changes may be committed, pushed through a feature branch and pull request, and
  merged after green CI. Do not create a release tag, GitHub Release, or public release APK
  in this task.

## UA Compatibility Layer

The following behavior is authoritative and must survive every ported batch.

### Android identity and updates

- Application id remains `com.lampaua.player`.
- The signed APK must use certificate SHA-256
  `749d118bc8a16a7c0464b8dd0498c53da8a86a668d8f09f551e60cf7d88ee15e`.
- Update checks and in-app installation use only `Hlushok/lampaua-player` releases and the
  UA FileProvider path. No Just+ release URL, package id, icon, or product name may enter a
  user-facing build.

### LampaUA and official LAMPA input

UA Player continues to accept both the official public contract and the richer private
contract:

- `ACTION_VIEW`, `ACTION_SEND`, HTTP headers, position, title, poster, return-result, and
  subtitle extras;
- official `video_list`, `video_list.name`, `video_list.filename`,
  `video_list.thumbnail`, `video_list.segments`, `video_list.season`,
  `video_list.episode`, `video_list.imdb_id`, `video_list.tmdb_id`, `video_list.id`, and
  `video_list.subtitles`;
- `quality_levels`, `quality_urls`, and per-episode indexed quality arrays;
- `lampaua.playlist_json`, `lampaua.playlist_index`, `lampaua.auto_next`, IPTV metadata,
  media type, external ids, and per-item resume state.

An upstream launcher parser may extend this list, but it may not narrow, rename, or bypass
the UA parser.

### Playback result contract

- Finish with `com.mxtech.intent.result.VIEW` where requested.
- Preserve `end_by`, `position`, `duration`, current URL, playlist index, and the per-item
  playback result map.
- When the next episode never reaches a playable state, report the last episode that
  actually played. Port the Just+ fix through `LampaPlaylist` rather than replacing the UA
  result path.

### UA recovery and media behavior

The new upstream recovery signals feed the existing UA policies instead of creating a
parallel retry system:

- `LoadWatchdogPolicy`, `PlaybackRecoveryPolicy`, `LiveRecoveryPolicy`, and stable-playback
  retry resets;
- resolver control responses, extensionless HLS handling, stream-type fallback, alternate
  URL and lower-quality selection;
- DV profile 7 conversion/fallback, decoder compatibility mode, AV1 fallback, tunneling,
  passthrough rebuilds, audio-output recovery, boost, and frame-rate policy;
- torrent-backed progress detection, IPTV/live-window recovery, and diagnostic redaction.

Every recovery action remains item-scoped and bounded. Subtitle, room, or skip network
failures never spend playback recovery attempts.

## Integration Strategy

### Rejected: wholesale source replacement

Copying Just+ `PlayerActivity`, `Prefs`, `SettingsActivity`, and resources wholesale would
delete UA playlist, result, resolver, update, branding, recovery, subtitle-translation, and
test code. This is not an acceptable shortcut.

### Rejected: rebase UA onto Just+

Using Just+ as a new base and replaying UA changes would make future upstream comparison
slightly simpler, but the current divergence is too large. It would turn verified UA
behavior into a broad reimplementation and make regressions hard to attribute.

### Selected: parity batches with adapters

Small, isolated upstream classes may be adapted directly under the Unlicense. Behavior
embedded in large Android classes is reimplemented behind UA helper classes and then wired
into the existing activity. Each batch begins with regression tests, compiles independently,
and must preserve all earlier batches.

## Batch 0: Baseline and Contract Guardrails

Before importing functionality:

- preserve the current uncommitted empty-state and compact-control changes;
- run the current unit suite and record the baseline failures, if any;
- add or strengthen contract tests for package/version, UA update repository, official and
  private LAMPA extras, playlist result output, FileProvider, branding resources, and hidden
  provider settings;
- add a source guard that rejects Just+ package names, release URLs, and branding in UA
  production resources;
- keep the existing signing key outside tracked files.

This batch creates the safety net used by all later batches.

## Batch 1: Complete Subtitle Platform

Port the complete Just+ `v1.3.0` subtitle model and merge it with the current UA subtitle
work.

### Language and appearance

- Replace the audio-only dialog with a shared `LanguagePriorityDialog` for ordered audio,
  primary subtitle, secondary subtitle, and translation-target languages.
- Keep Ukrainian first by default while allowing the user to choose another target.
- Retain UA's live subtitle preview and navy/gold preference styling.
- Support embedded-style override, bold, scale, text color, background, edge, and separate
  secondary-line appearance.
- Prevent unreadable opaque foreground/background combinations.

### Search and title resolution

- Port `TitleSearch`, Just+ `MediaId`, and the full `SubtitleSearch` candidate model.
- Search by IMDb/TMDB ids when supplied by LAMPA, enrich one id from the other only when a
  source requires it, and support a manually typed title when ids are absent or wrong.
- Reuse valid cached subtitles before network work.
- Reject another cut, season, or episode when duration and episode identity do not match.
- Infer language from the downloaded filename when provider metadata is empty.
- Handle OpenSubtitles redirect/advertisement links without displaying HTML as subtitles.
- Keep API keys and endpoint details out of settings and logs.

### Translation

- Port the Just+ translation pipeline and backend fallback model.
- Translate to the user's selected target language; default to Ukrainian.
- Batch requests with bounded cue and byte limits, validate cue mapping, preserve timing and
  formatting, and write cache files atomically.
- Never display a partially translated document or label a foreign file as translated.
- Keep the current UA privacy rule: send cue text only, never media URLs, external ids,
  filenames, room state, headers, or credentials.
- A translated cache entry is distinct from an original subtitle and never overrides a
  later original-language result.

### Hot attach, offset, and secondary line

- Keep `SubtitleTimeline` and `SubtitleOffset`, upgrading them to the final v1.3 behavior.
- Attach a found or translated subtitle without rebuilding video whenever Media3 can parse
  it; retain the existing rebuild path only as a fallback.
- Let searches survive a player rebuild but cancel safely when media identity changes.
- Add `SecondarySubtitles` and `SecondaryTextTrack` for a second language line.
- The second line follows the approved Just+ behavior, including pause-only display mode
  and the corrected placement of the translation hint above the line it describes.
- The offset panel exposes independent primary and secondary sliders without clipping.
- Subtitle offset remains session/item scoped and resets on episode changes.

### Subtitle UI

- Adapt Just+ side panels to UA styling and the compact `More` grouping.
- Offer primary track, secondary track, online search, manual title search, translation,
  timing, and appearance without exposing raw provider switches.
- Keep TV focus deterministic and return focus to Play/Pause after panel dismissal where
  appropriate.

## Batch 2: Stream, Torrent, and Decoder Reliability

### Torrent and stalled-buffer refill

- Port the larger rebuffer target used after a midstream stall instead of resuming as soon
  as roughly two seconds are available.
- Continue to treat incoming bytes and moving buffered position as progress. Do not show a
  lost-stream message while buffered playback is still moving.
- Keep transfer-rate text tied to the loading state and always hide it on every transition
  back to `STATE_READY`.
- Do not rebuild a still-alive torrent source merely because it is slow.

### Frozen video with continuing audio

- Track rendered video progress independently from player position and audio progress.
- Detect a video renderer that stopped producing frames while playback time and audio keep
  moving.
- Route the signal through UA decoder compatibility and bounded recovery policies.
- Avoid false positives for audio-only media, paused playback, seeking, backgrounding,
  surface changes, frame-rate switching, and live-window rollover.

### HTTP Range compatibility

- Port the initial whole-file `Range` request needed by servers that refuse a plain first
  request.
- Implement it in the UA data-source chain so API headers, resolver inspection, transfer
  counting, redirects, and sanitized diagnostics continue to work.
- Do not send a conflicting range for HLS/DASH manifests or requests where Media3 already
  specifies a byte range.

### Slow software decoder fallback

- Detect software decoding only when decoder name, resolution, frame delivery, buffer, and
  dropped-frame evidence agree that decode speed is the bottleneck.
- Prefer a lower launcher-provided or adaptive variant before declaring a source failure.
- Keep UA's AV1, Dolby Vision, HEVC, tunneling, and device-learned decoder fallbacks ahead of
  a terminal error.
- Explain software decoding in the diagnostic report without exposing the media URL.

## Batch 3: Playlist, Activity, TV, and Control Fixes

### Last playable episode result

Track the last item that reached `STATE_READY`. If automatic next-item startup fails before
the new item becomes playable, write position and result data for the previous playable
item, while retaining the attempted index only in local diagnostics.

### Single player instance

- Keep the activity `singleTask` and merge upstream `onNewIntent` behavior with UA launcher,
  room invite, subtitle, `ACTION_SEND`, and `ACTION_VIEW` handling.
- A second external launch replaces media in the existing activity without leaving a hidden
  second player or losing the result contract.
- A launcher-icon `ACTION_MAIN` with no stream shows the UA empty state and does not resume
  stale media.

### TV controls

- Keep controls visible while D-pad focus is moving between rows or panels.
- Preserve UA's strong blue/gold focus, scaling, Play/Pause focus restoration, accelerated
  TV seeking, compact pinned controls, and grouped `More` menu.
- Add a setting for single-press Back on TV while keeping the UA double-Back default.
- Add a setting to keep the screen awake while paused. Playback always keeps it awake;
  empty state and stopped playback do not.
- Ensure panel focus has one visual owner and returns to a predictable control.

## Batch 4: Skip Session Scope and Source Parity

### Source ordering

Use this priority:

1. segments supplied by the launching LAMPA/LampaUA session;
2. the UA Lampac server API/cache;
3. the adapted Just+ multi-source finder and voting logic.

Direct sources supplement missing categories and do not overwrite a higher-priority segment
without an explicit confidence rule. The player remains independent of Alloha and Kodik.

### Session controls

- Port per-session skip-mode decisions and manual timing offset.
- Keep separate intro/recap/ad/credits behavior and UA automatic/manual/brief/full modes.
- Draw adjusted segments on the timeline and apply the same adjusted times to button,
  automatic skip, cancel, and undo actions.
- Reset manual offset on media session/activity end; do not silently persist it across
  unrelated films.
- Keep Watch Together episode and seek synchronization authoritative after a skip.

## Batch 5: Settings and UA Presentation Convergence

- Merge new subtitle, TV, decoder, and skip settings into the UA hierarchy rather than
  copying Just+ screens wholesale.
- Keep the subtitle live preview at the bottom of appearance settings.
- Keep provider and backend switches debug-only/internal.
- Preserve the compact player-button settings: Play/Pause and More are mandatory; unpinned
  available actions move into grouped More menus rather than disappearing.
- Apply UA terminology and Ukrainian translations across every new screen and error.
- Retain English and Russian resource fallbacks without allowing stale translations to fail
  release lint.

## Error Handling and Privacy

- All network operations are bounded by timeouts, cancellation generation, and item
  identity checks.
- Subtitle search/translation, skip lookup, update checks, and room traffic have independent
  failure domains.
- No background service uploads diagnostics automatically.
- Manual diagnostic sharing removes credentials, query strings, signed paths, tokens, and
  room passwords.
- Invalid external metadata falls back to ordinary playback rather than crashing intent
  parsing.
- A failed optional feature never prevents local media playback.

## Testing Strategy

Tests are written before or with each behavior rather than after the final merge.

### JVM tests

- LAMPA official/private input and MX-style result contracts;
- media identity, title matching, language inference, candidate ranking, cache precedence,
  and wrong-cut rejection;
- translation batching, response validation, target-language selection, cancellation, and
  atomic cache naming;
- primary/secondary timeline lookup, offset direction, independent sliders, pause-only
  secondary display, and item reset;
- torrent rebuffer thresholds, byte-progress decisions, frozen-video detection exclusions,
  Range header policy, and software-decoder fallback selection;
- last-playable playlist result behavior and new-intent single-instance policy;
- TV Back and keep-screen-on policies;
- skip source priority, voting, session offset, cancel, undo, and reset behavior;
- source/resource guards for package, branding, updater, hidden endpoints, version, and
  signature expectations.

### Android build verification

After each batch run focused tests and the affected variant compilation. Before producing
the local APK run:

- full unit tests;
- Android lint;
- latest universal debug build;
- latest universal release build;
- `git diff --check` and a review of all changed/untracked files;
- APK alignment and `apksigner verify --verbose --print-certs`;
- independent package, version name, version code, native ABI, certificate SHA-256, and APK
  SHA-256 checks.

### Device verification

When an ADB device is available, verify:

- launcher empty state and external LAMPA launch;
- online search, manual title search, target-language translation, hot attach, dual
  subtitles, pause-only mode, and both offsets;
- torrent stall recovery, Range-only HTTP server, frozen video recovery, and lower-quality
  software-decoder fallback;
- playlist next-item failure result;
- TV D-pad focus, Back modes, paused screen-on setting, lock timeout, and compact More menu;
- skip priority/offset and Watch Together interaction.

Automated tests cannot prove vendor decoder behavior, real torrent buffering, third-party
subtitle availability, or two-device room synchronization. Any unavailable device surface
is reported explicitly rather than inferred from a successful build.

## Delivery Boundary

Implementation uses a dedicated feature branch and reviewable commits. After complete local
verification it may be pushed through a pull request, must wait for green CI, and may be
merged. It must not create or move a release tag, create a GitHub Release, upload a public
release APK, or change the in-app stable release feed. The validation deliverable includes a
locally signed `2.0.0 (20)` APK, verification results, and a clear list of device-level checks
that were or were not performed.
