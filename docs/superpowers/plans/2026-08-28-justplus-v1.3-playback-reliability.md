# Just+ v1.3 Playback Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Just+ v1.3 torrent rebuffering, frozen-video detection, Range-only server compatibility, and slow software-decoder fallback without duplicating or weakening UA recovery policies.

**Architecture:** Put each decision in a pure Java policy and keep Android/Media3 actions in `PlayerActivity`. Feed new evidence into the existing item-scoped recovery state, resolver data-source chain, quality variants, and sanitized diagnostics.

**Tech Stack:** Java 8, Media3 ExoPlayer/DefaultLoadControl/DefaultHttpDataSource, OkHttp-adjacent UA resolver chain, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-08-28-justplus-v1.3-parity-design.md`

## Global Constraints

- Keep `com.lampaua.player`, `2.0.0 (20)`, UA branding, LAMPA contracts, and current signing identity.
- Preserve resolver headers, extensionless HLS, live-window recovery, DV7, AV1, tunneling, passthrough, and audio recovery.
- Recovery is item-scoped, bounded, and reset only after stable playback.
- Do not show a reconnect message while buffered playback or network transfer is making progress.
- Do not create a release tag, GitHub Release, or public release APK.
