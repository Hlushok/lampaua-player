# Just+ v1.3 Activity, TV, and Playlist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Just+ v1.3 last-played episode reporting, single-player activity handling, D-pad controller retention, TV Back mode, and paused screen-on behavior while preserving UA empty state and LAMPA result contracts.

**Architecture:** Keep playlist/result, launch-intent, TV Back, screen-on, and focus decisions in pure policies. `PlayerActivity` owns Android lifecycle wiring; `LampaPlaylist` remains the authoritative UA episode/result model.

**Tech Stack:** Java 8, Android Activity/Intent/Window APIs, Media3 PlayerView, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-08-28-justplus-v1.3-parity-design.md`

## Global Constraints

- Preserve official LAMPA and `lampaua.*` inputs and `com.mxtech.intent.result.VIEW` output.
- Preserve launcher empty state: no stale replay on `ACTION_MAIN` without media.
- Keep `singleTask`, Android 13 back dispatcher, UA double-Back default, TV focus, and compact controls.
- Keep `2.0.0 (20)`, `com.lampaua.player`, UA branding, and signing identity.
- Do not create a release tag, GitHub Release, or public release APK.
