# Just+ v1.3 Parity Verification and Delivery Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the combined Just+ v1.3 parity work preserves UA contracts, builds correctly, produces a compatible locally signed APK, and reaches green review/CI without publishing a release.

**Architecture:** Verification is layered from source contracts to JVM tests, Android lint/builds, APK identity/signature checks, and device scenarios. GitHub source delivery is separated from release publication so no tag or release asset can be created accidentally.

**Tech Stack:** Gradle/AGP, JUnit 4, Android lint, aapt, zipalign, apksigner, Git/GitHub CLI, ADB when available.

**Spec:** `docs/superpowers/specs/2026-08-28-justplus-v1.3-parity-design.md`

## Global Constraints

- Package `com.lampaua.player`, version `2.0.0`, version code `20`.
- Required certificate SHA-256: `749d118bc8a16a7c0464b8dd0498c53da8a86a668d8f09f551e60cf7d88ee15e`.
- No release tag, GitHub Release, public release APK, or stable updater-feed change.
- Preserve UA branding, LAMPA official/private contracts, MX result output, update repository, and privacy redaction.
- Do not claim runtime behavior that was not tested on an attached device.

### Task 3: Local Signing and APK Identity

**Files:**
- Generate: `app/build/outputs/apk/local-private/UA-Player-2.0.0-private.apk`
- Do not track: signing keystore, passwords, generated APK/idsig files.

**Interfaces:**
- Consumes: aligned unsigned release APK and the existing compatible local key.
- Produces: locally installable APK with verified identity and digest.

- [ ] **Step 1: Verify unsigned release alignment**

Run build-tools `zipalign -c -P 16 -v 4` and require `Verification successful`.

- [ ] **Step 2: Verify signing key certificate before signing**

Use `keytool -list -v` without printing passwords. Require the exact approved SHA-256 certificate.

- [ ] **Step 3: Sign the release APK locally**

Use `apksigner sign` with v1/v2/v3 enabled and v4 optional/off for the standalone APK. Write only under ignored build outputs.

- [ ] **Step 4: Verify the signed APK**

Run `apksigner verify --verbose --print-certs`, `zipalign -c`, and `aapt dump badging`. Require one signer, package `com.lampaua.player`, version code `20`, version name `2.0.0`, expected ABIs, and exact certificate digest.

- [ ] **Step 5: Compute SHA-256 and size**

Use `Get-FileHash -Algorithm SHA256` and record absolute path, byte size, timestamp, and lowercase digest.

### Task 4: Device Verification When Available

**Files:**
- No source edits unless a reproduced defect requires a new red/green cycle.

**Interfaces:**
- Consumes: verified local APK and an ADB device.
- Produces: observed runtime results or an explicit unavailable-device statement.

- [ ] **Step 1: Check devices**

Run `adb devices -l`. If empty, record device verification as not performed and do not infer success.

- [ ] **Step 2: Install over the current UA Player**

When a device is present, use `adb install -r` and require success without uninstalling, proving signature compatibility.

- [ ] **Step 3: Exercise critical launch/contracts**

Test launcher empty state, file open, external ACTION_VIEW, official LAMPA playlist fixture, result return, and a second intent reusing one activity.

- [ ] **Step 4: Exercise new feature paths**

Test subtitle search/manual title/translation/secondary/offset, torrent stall, live/HLS recovery, Range-only URL, software decode fallback where reproducible, TV Back/screen-on/focus, skip priority/session offset, and Watch Together.

- [ ] **Step 5: Capture diagnostics for any failure**

Use UA's local report, logcat, and deterministic steps. Add a regression test before changing code, then rerun Tasks 1-4.

### Task 5: Branch, PR, CI, and Merge Without Release

**Files:**
- Commit: source, tests, resources, design, and plans only.
- Exclude: APKs, keystores, local properties, reports, caches, and temporary upstream checkout.

**Interfaces:**
- Consumes: fully verified tree.
- Produces: reviewed source in the repository while stopping before release publication.

- [ ] **Step 1: Review commits and working tree**

Ensure checkpoint commits are coherent, no generated/private files are tracked, and `git diff --check` is clean.

- [ ] **Step 2: Push the feature branch**

Push only after local verification. Never push a version tag.

- [ ] **Step 3: Create or update the feature PR**

Describe upstream `v1.3.0` commit, UA-specific adaptations, tests, APK verification, runtime gaps, and the explicit no-release boundary.

- [ ] **Step 4: Wait for all required CI checks**

Inspect failures, reproduce locally where possible, fix with new tests, push, and wait again. Do not merge red CI.

- [ ] **Step 5: Merge after green CI**

Merge using the repository's normal PR method if all required checks are green and no unresolved review findings remain.

- [ ] **Step 6: Verify no release publication occurred**

Check tags, GitHub Releases, and updater feed. Require no new/moved tag and no new release/asset. Do not run the release workflow.
