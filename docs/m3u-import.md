# Імпорт M3U з TorrServe

TorrServe має два різні маршрути зовнішнього запуску: звичайний вибір файлу
передає вкладений `playlist` Bundle, а кнопки «Плейлист» / «Продовжити»
передають HTTP URL M3U як `video/*`. «Продовжити» додає `fromlast`;
визначення першої серії залишається на стороні TorrServer.

UA Player завантажує такий список поза UI-потоком і перетворює його на
власний `PlaylistApi`. Порядок, назви EXTINF і URL зберігаються; відносні
посилання розв'язуються від фактичного URL після redirect. Позиції M3U
починаються з нуля, без підміни результату `fromlast` локальною історією.

Будь-який тег `#EXT-X-` означає HLS: оригінальний URI, MIME і extras
залишаються для Media3. Явні Bundle/JSON/`video_list` API не імпортуються
повторно. Успішно імпортований Bundle переживає recreation без нового fetch;
незавершений запит після recreation можна повторити. Пізня відповідь старого
запуску не замінює нове відео й не запускає відео у фоні.

Межі: 1 MiB тексту, 500 елементів і 256 KiB серіалізованого Bundle.
Надмірний або порожній список відхиляється, а не мовчки обрізається.
Підтримуються HTTP(S), локальні file/content URI. Віддалений список не
може посилатися на локальні file/content ресурси. Заголовки `Authorization`,
`Cookie`, `Proxy-Authorization`, отримані у вхідному Intent, не переносяться
між origin при redirect чи для елементів списку. Без переданих облікових
даних цей адаптер не може отримати доступ до захищеного сервера від імені
іншого застосунку.

Тести: parser/HLS, relative URL, назви з комами, limits, origin-захист,
реальний loopback HTTP GET/redirect, fromlast, cancellation, activity recreate,
оновлений Intent і повернення з фону. Публікація проходить штатні CI,
release lint, перевірку пакета/ресурсів/сертифіката та завантаження APK.
